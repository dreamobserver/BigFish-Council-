# 使用流程（人类视角）

## 典型一次协作

### 1. 建任务（任务页）
填标题、目标、范围、风险等级、Prompt 正文。刚建时为「草稿」。

### 2. 送审
点「送审」，状态变「议事中」。此时可以把 Prompt 复制到 ChatGPT / Gemini 那边讨论。

### 3. 录入两个模型的审查意见（议事页）
左右两个编辑框分别贴 GPT 和 Gemini 的回复，然后：

- 「保存为评论」→ kind=comment，**不计票**，只留记录。
- 「投 approve」/「投 reject」→ kind=vote，计入票数。

必须两个模型**对同一版本**都投 approve，状态才会自动进「等待审批」。
只要有一票 reject 就不会往下走。

### 4. 改 Prompt（如果审查要求改）
在任务页改 Prompt 后保存 → 自动生成新版本（v2、v3…），**旧版本的票全部作废**，
状态回到「议事中」，两个模型要重新对 v2 投票。
议事页可以选任意两个版本看 unified diff。

### 5. 人类审批（审批页）
看到「目标 / 范围 / 风险 / 双模型审查 / 最终 Prompt」的完整快照，然后：

- **批准并派工** → 状态 APPROVED，云端执行器可领取。
- **退回修改** → 回「已退回」，改完再送审。
- **拒绝** → 任务终止。

这一步只有本机 GUI 能做，HTTP/MCP 里没有对应接口。

### 6. 云端执行（自动）
DSH 侧执行器通过 MCP 调到 council_claim_task 拿到 Prompt 和一次性 ticket，
过程中用 council_heartbeat 报进度。你在监控页能看到心跳、日志、Diff、测试结果。
超过 120 秒没心跳会自动转「已阻断」。

### 7. 验收（监控页 / 审批页）
执行器回传后状态是「待验收」，**不是完成**。你看过日志和 Diff 后点：

- **验收通过** → DONE。
- **不通过** → 打回，可要求重做。

## 暂停 / 取消

监控页有「请求暂停」「请求取消」，只是给任务打标记，执行器下次心跳时会收到
pause: true / cancel: true。**它不会强杀云端进程**，因为设计上不给云端
反向控制本机的能力。

## 备份

设置 → 备份导出，生成一个 zip（含数据库快照 + 全部事件）。
恢复：解压后用 --data-dir 指向解压出来的目录启动即可。
